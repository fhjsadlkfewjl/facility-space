# Статус пилота — 15 ноября 2026

**Рабочий пилот на реальных данных, доступен владельцу по https://2.29.173.184. Не корпоративная эксплуатация.**

## Готово

- Серверный сервис: React + API + PostgreSQL; Docker на Hetzner, доверенный HTTPS по IP, автоматическое продление. Работает без Mac.
- Перенесённая структура: 14 импортированных зданий + тестовое; 58 активных импортированных этажей с исходными SVG, 19 неактивных + тестовый этаж. 1 758 помещений, 4 670 объектов мебели, 4 130 мест. Координаты, углы и связи сохранены.
- Employee: карта, поиск людей, своё место, самостоятельное назначение/перенос/снятие, бронирование. АХО: помещения и места, пересадка, инвентарь, импорт, редактор, история и проверка данных.
- Реализованы CSV preview → проверка → применение; мастер нового здания; SVG и мебель; калибровка/площади; инвентарные номера; парковка; площади/стоимость; аренда; аудит/версии. Это существующие возможности кода, не обещание полной приёмки каждого сценария.
- «Сегодня»: быстрые действия и один счётчик качества, без превращения старых замечаний в ежедневные задания.

**Проверено сейчас:** живые API и данные для трёх ролей; открытие экранов employee/АХО; сборка; 6 точечных тестов self-service/прав/бронирования/импорта/нового здания на отдельной тестовой базе; обновление реального staging. Полный QA и массовые изменения staging не проводились.

## Нужны реальные данные / подтверждение компании

- Официальные площади, контрольные размеры и классификация. В очереди: 806 помещений без официальной площади; 56 этажей без масштаба. Контур не равен подтверждённому обмеру.
- Инвентарные номера и решения по 547 записям карантина. Спорные назначения не выбираются автоматически.
- Реальные тарифы, парковка, арендаторы/договоры: сейчас соответствующие реестры пусты. Это возможности сервиса, а не введённый учёт компании.
- Ответственные за здания: сейчас 0 записей. У роли `facilities` часть данных и действий ограничена зоной ответственности. Для полного показа АХО использовать доверенный admin-доступ; до самостоятельной приёмки АХО назначить зоны ответственности.
- АХО подтверждает правила назначения, бронирования, площади и 8 основных сценариев.

## Нужен IT

Корпоративное размещение/ответственный за эксплуатацию; SSO и стабильный ID; обновление сотрудников/подразделений; роли и зоны доступа; ссылка из Bitrix (куда вести и кому видна); резервирование вне VPS, мониторинг, восстановление и production deployment.

**Критичное ограничение доступа:** текущий общий демонстрационный ключ позволяет выбрать роль суффиксом. Это не безопасные отдельные аккаунты сотрудников. Не раздавать его широкому кругу пользователей. 1–3 доверенных представителя АХО могут участвовать в контролируемом показе; для независимого доступа нужны согласованные права и изолированные учётные записи.

**Реально осталось нам:** исправить блокирующие замечания приёмки, согласовать и проверить доступ АХО, подготовить передачу IT. Не расширять функции. Критерий завершения пилота: согласованный набор сценариев принят владельцем/АХО, известные ограничения записаны, обновление и восстановление понятны.
