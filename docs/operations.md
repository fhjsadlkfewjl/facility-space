# Локальный запуск и требования к размещению

Обслуживание текущего VPS описано в [эксплуатации](operations-ru.md). Ниже — отдельный локальный запуск с тестовыми данными.

## Docker

Скопируйте `.env.example` в `.env`. Задайте свой `POSTGRES_PASSWORD` и соответствующий `DATABASE_URL`. Внутри Compose пароль передаётся отдельно; в URL специальные символы нужно кодировать.

```sh
docker compose up --build -d
docker compose ps
docker compose logs --tail=100 api web
curl --fail http://127.0.0.1:8080/health
```

В этой конфигурации интерфейс и PostgreSQL доступны только с локального компьютера. Используются демонстрационный вход и тестовый набор. `/health` проверяет соединение с базой.

## Корпоративное размещение

- `NODE_ENV=production`, `AUTH_MODE=oidc`, `SEED_DEMO=false`; `VITE_DEMO_TOKEN` при сборке пуст. [Настройка входа](auth-integration.md).
- Миграции выполняются отдельно командой `npm run db:migrate`. У приложения `RUN_MIGRATIONS=false` и отдельная роль базы без административных прав.
- Права базы подбираются по операциям приложения; на `audit_log` и `layout_versions` не выдаются права изменения и удаления истории. Работа с миграциями и импортом требует отдельных прав.
- Для удалённой PostgreSQL нужна проверка TLS доверенным центром сертификации; `rejectUnauthorized=false` не использовать.
- IT настраивает HTTPS, сетевой доступ, хранение секретов, копии, журналы, уведомления и сроки хранения персональных данных.

Назначения и брони меняются через API. Прямые записи в базу обходят проверку пересечений, которую выполняет сервис.

## Проверка локальной резервной копии

```sh
mkdir -p work
docker compose exec -T db pg_dump -U office -d office -Fc > work/facility.backup
docker compose exec db createdb -U office office_restore_check
docker compose exec -T db pg_restore -U office -d office_restore_check --exit-on-error < work/facility.backup
```

Восстановление выполняется в отдельную пустую базу. Реальные дампы и `.env` в Git не добавляют.

## Первичный импорт

Начальная загрузка выполняется в пустую базу. При заданном `DATABASE_URL` предварительный запуск применяет миграции схемы, но откатывает импортируемые данные; без него используется отдельная PGlite. Для сохранения нужен `--apply`.

Повтор одного снимка не дублирует записи. Новый снимок требует [сверки](sync-strategy.md). SVG загружаются отдельно от SQL-выгрузки; физические размеры и масштаб подтверждаются отдельно.
