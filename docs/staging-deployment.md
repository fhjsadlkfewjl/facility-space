# Размещение тестового сервера

Текущий адрес: https://2.29.173.184. Сервер работает отдельно от локального компьютера. Данные не синхронизируются между ними автоматически.

## Что перенесено

15 ноября 2026 года сохранённая локальная база перенесена в PostgreSQL 17. В копию вошли здания, этажи, комнаты, исходные SVG, мебель, координаты, сотрудники, назначения, брони и история. Обезличивание и повторное заполнение демонстрационными данными не выполнялись.

В исходном пакете: 14 импортированных зданий и одно тестовое; 58 активных и 19 неактивных импортированных этажей и один тестовый. 58 подложек этажей, 1 758 помещений, 4 670 предметов мебели и 4 130 рабочих мест. Полные количества включают неактивные записи и не равны числу строк в обычном меню.

При восстановлении проверены содержимое таблиц, связи и последовательности. Позднейшие изменения сервера в этот снимок не входят.

## Доступ

Caddy обслуживает HTTPS. Экран входа доступен публично; API с офисными данными требует токен. PostgreSQL и внутренние порты приложения наружу не опубликованы.

Общий демонстрационный код позволяет выбрать роль. Для персонального доступа сотрудников требуется [корпоративный вход](auth-integration.md).

## Обновление

В корне локального проекта:

```sh
bash scripts/update-staging.sh
```

Команда выпускает код через проверку кандидата на восстановленной копии. Она не должна заменять рабочую базу локальным снимком. Изменения схемы требуют отдельного плана. Подробности и откат: [эксплуатация](operations-ru.md).

Для проверки на VPS:

```sh
cd /opt/facility-space
docker compose --env-file .env.staging -f compose.staging.yaml ps
docker compose --env-file .env.staging -f compose.staging.yaml logs --tail=80 api caddy
```

Не повторяйте `init` на работающем сайте и не выполняйте `docker compose down -v`: это может удалить данные.

Новый сервер поднимают по [инструкции восстановления](../deploy/handoff/RESTORE.md). Сертификат и продление описаны в [HTTPS по IP](staging-ip-https.md).
