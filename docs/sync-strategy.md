# Обновление данных из старой системы

Сейчас используется импорт сохранённого снимка. Автоматической синхронизации сотрудников и записи обратно в Bitrix нет.

## Подготовка

SQL-выгрузка обрабатывается локально. Данные редактора и SVG берутся из сохранённых материалов или согласованного чтения портала. `scripts/editor-requests.mjs` готовит запросы; сбор выполняется явно. Точный ответ «Этаж не найден» можно пропустить, другие ошибки останавливают сбор.

Преобразование сохранённого снимка:

```sh
python3 scripts/extract-editor-snapshot.py capture.json staging.json evidence-output --assets assets.json
```

Импорт проверяет схему и SVG. `scripts/reconcile-evidence.ts` сравнивает объекты по исходным идентификаторам. Повтор того же снимка не дублирует записи.

## Новый снимок

1. Загрузить его в отдельную базу.
2. Сравнить добавления, изменения и отсутствующие записи.
3. Согласовать спорные связи и сохранение ручных правок.
4. Применить утверждённые изменения с записью в историю.

Отсутствующие в новом снимке объекты нельзя автоматически удалять из рабочего учёта.

Для регулярного обновления IT должен предоставить источник, постоянный ID сотрудника, период обновления и правила увольнения, повторного приёма и изменения подразделения. [Вопросы IT](it-questions-final.md).
