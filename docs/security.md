# Доступ и защита данных

## В приложении

API проверяет роль и права на изменение здания. Личные действия сотрудника используют его идентификатор из проверенной сессии. Назначения и брони проверяются на конфликты в транзакции.

Входные данные проходят проверку; SQL использует параметры. SVG проверяется перед сохранением, экспорт CSV защищён от выполнения формул. Предварительный просмотр импорта связан с пользователем, ограничен по времени и применяется один раз. Устаревшая версия плана или импорта отклоняется.

Журнал и версии защищены от перезаписи на уровне базы. Администратор самой базы может менять её схему — это не неизменяемое внешнее хранилище.

## При размещении

- Использовать HTTPS и личный [корпоративный вход](auth-integration.md).
- Не публиковать порт PostgreSQL. Выделить приложению роль базы без административных прав; миграции запускать отдельно.
- Хранить секреты и резервные копии вне Git, ограничить доступ и согласовать сроки хранения.
- Настроить копии вне сервера, уведомления и регулярное восстановление.

Текущий демонстрационный код позволяет выбрать роль. Он предназначен для доверенных участников проверки, а не для выдачи всем сотрудникам.

Публичный репозиторий содержит исходники и тестовые данные. Реальная база, планы, исходные выгрузки и доступы передаются отдельно. Автоматические тесты проверяют отдельные риски; независимая проверка безопасности корпоративного размещения остаётся задачей IT.
