# Передача Facility Space

## Что передать

Получателю нужны два отдельных комплекта:

1. **Основной комплект:** `site.tar.gz.enc`, `site.sha256`, эта инструкция и `restore.py`.
2. **Доступы — отдельно:** `archive.key` и `server.env`. Не отправляйте их вместе с основным комплектом и не добавляйте в Git.

В зашифрованном архиве: текущая база с сотрудниками, назначениями, бронированиями, помещениями, SVG-планами и мебелью; готовые образы приложения и PostgreSQL; файлы серверной версии без файла паролей. `manifest.json` содержит контрольные суммы и перечень таблиц.

Это копия на указанное в manifest.json время. Более поздние изменения рабочего сайта в неё не входят. Исходные выгрузки старого портала не нужны для запуска этой копии и в комплект не включены.

## Восстановление для IT

Нужен Linux x86-64 с Docker Engine, Docker Compose v2, Python 3.11+ и OpenSSL 3+. Образы сохранены с текущего Linux-сервера. Для другого процессора нужна отдельная подготовка.

Работайте на новом сервере или в отдельном каталоге. Скрипт создаёт новый проект и новую базу; существующий проект с тем же именем не перезаписывает. Миграции и заполнение демонстрационными данными не запускаются.

Поместите основной комплект в текущий каталог. Доступы храните отдельно, например `/root/facility-access/`, с правами только владельцу.

```sh
sha256sum -c site.sha256
mkdir restored-site
chmod 700 restored-site
openssl enc -d -aes-256-cbc -pbkdf2 -iter 600000 -md sha256 \
  -pass file:/root/facility-access/archive.key -in site.tar.gz.enc \
  | tar -xz -C restored-site
python3 restore.py --directory ./restored-site \
  --secrets /root/facility-access/server.env \
  --name facility-restore-company --port 18080
```

При ошибке остановитесь. Не повторяйте запуск поверх частично восстановленного проекта и не удаляйте рабочую базу. Успешное восстановление создаёт `restored-site/restore-result.json`: контрольные суммы всех таблиц сверены, вход проверен.

## Как открыть

Сайт после восстановления слушает **только 127.0.0.1:18080** на новом сервере. База наружу не публикуется. На своём компьютере откройте SSH-туннель:

```sh
ssh -L 18080:127.0.0.1:18080 пользователь@новый-сервер
```

Откройте http://localhost:18080. Для текущего демонстрационного входа используйте значение `DEMO_TOKEN` из отдельного `server.env` с суффиксом `:employee`, `:facilities` или `:admin` соответственно. Эти значения не публикуйте.

Для постоянного доступа по ссылке IT должен настроить HTTPS и корпоративную авторизацию. Не открывайте этот восстановленный HTTP-порт в интернет. После передачи смените пароли и токены на новом сервере: в server.env находятся действующие доступы исходной версии.

## Что проверить

Откройте здания и несколько этажей, найдите сотрудника, проверьте назначения и бронирования. Рабочий сайт при этом не затрагивается. Проверка механизма восстановления на временной копии приложена в `verification.json`.

Обновление и резервирование: `docs/operations-ru.md` в репозитории. Расписание резервных копий и HTTPS не устанавливаются скриптом restore.py автоматически — настройте их для нового сервера до штатной работы.
